The Task

"Map Okta attributes to application attributes"

Once an app is connected, its fields and Okta's profile fields need to agree on what data means the same thing. That agreement is the attribute mapping — and it has a direction.

The Mechanism

The Profile Editor lets you connect Okta user attributes to application attributes, making Okta either "the single source of truth for user data, or the recipient of user data."

Two directions exist: App to Okta (the app is the source, Okta receives) and Okta to App (Okta is the source, sending data out).

The Gotcha — Entitlement Management Apps

App integrations that use entitlement management use discovery to automatically map attributes.

For these apps, admins can't manually configure the mapping — it's auto-discovered. Don't go looking for a mapping screen that isn't there.

The Mechanism — Validation & Frequency

Before saving, verify all required attributes are mapped. The preview feature uses color-coding — green for valid, red for errors — so misconfigurations are visible before you commit.

An optional push frequency setting controls how often mapped attributes update in the target system.

The Angle — What Trips People Up

Watch for these in your own sandbox run:

→ Trying to hand-configure mapping on an entitlement-management app — it's automatic, not manual there.

→ Saving with a required attribute still showing red in the preview — it needs to be resolved first.

One Line To Remember

Attribute mapping in the Profile Editor has a direction: App to Okta, or Okta to App. Entitlement-management apps auto-discover mappings — no manual config. Required attributes must be mapped before saving; the preview shows green (valid) / red (error). Push frequency controls update cadence on Okta-to-App mappings.
